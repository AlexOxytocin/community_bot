# Активности, подписки и bot-first onboarding — выпуск схемы 0038

## Поведение и границы

- Источник: настроенный community_telegram_chat_id, любая тема. Название темы не влияет.
- Реальные hashtag entities в тексте/подписи: #online, #offline, #nomad, #important,
  #crypto без учёта регистра.
- Автор — активный администратор приложения, включая суперадминистратора.
  Права Telegram сами по себе не назначают роль в приложении.
- Пересылки, анонимные публикации, боты, посты участников/модераторов игнорируются.
- Подписки: важные обновления, цифровой кочевник, взаимопомощь, онлайн-ивенты,
  офлайн-ивенты и крипта. Взаимопомощь управляет всеми уведомлениями заданий и споров
  одним переключателем; детальная настройка пользователю не показывается.
  Карма, уровни и ачивки не являются источниками рассылки.
- Один получатель получает одно уведомление на сообщение/альбом даже при нескольких тегах.
  Перед отправкой повторно проверяются подписка, членство и доступность события.
- Изменённые сообщения обновляют теги. Удаление тега отменяет ещё не отправленную
  рассылку; уже доставленное сообщение не отзывается. Удаление самого поста не является
  поддерживаемым событием Bot API и не гарантирует отмену очереди.
- Неопределённый результат внешней отправки не повторяется автоматически: возможна
  недоставка, но не автоматический дубль. Ошибка обозначается delivery_uncertain.
- Сохраняется существующее окно доставки с учётом часового пояса участника.
- Подписки в боте и Mini App общие и меняются одним нажатием без подтверждения.
  У нового участника по умолчанию включены важные обновления и цифровой кочевник;
  остальные направления выключены. Существующие согласия миграция не расширяет.
- `/start` представляет бота сообщества «Алло, Нейросеточная», объясняет пользу и
  предлагает вступить в чат. Профиль создаётся только после подтверждённого вступления;
  органическое вступление без запуска бота профиль не создаёт. После выбора подписок
  Mini App остаётся необязательным и открывается только по желанию пользователя.

## Локальная приёмка

Проверить плитки на 320/390 px, сохранение после перезагрузки, конфликт двух устройств,
подтверждение отключения важных уведомлений, отсутствие уведомлений активности чата.
Бот: Start → знакомство → вступление/повторная проверка членства → автоматический профиль
при simplified → выбор подписок → завершение без принудительного открытия Mini App.
Нижняя клавиатура: «Активности и подписки», «Что за приложение?»; Mini App запускается
отдельной кнопкой.
Старая клавиатура продолжает безопасно открывать новые панели без автоматической подписки.

## Обязательные условия production release

Это план, не разрешение запускать команды и не свидетельство выполненного deployment.
Fast deploy нельзя применять: меняется Alembic head 0036 → 0037 → 0038.
Для этого выпуска ops/wallet_cutover.py поддерживает allowlisted переход
`--transition 0036-0038` (только при prepare). Apply/recover читают переход из receipt.
До запуска проверить digest exact source и dry preflight. Проверка миграций проходит
на отдельной drill-БД, восстановленная rollback-БД остаётся нетронутой.

1. Измерить exact SHA/image, live revision и Compose package через labels работающих
   контейнеров. Подтвердить services postgres, migrate, worker, web. Зафиксировать rollback.
2. Остановить writers, сделать свежий backup и проверить восстановление в изолированной БД.
   Проверить миграцию на восстановленной копии, согласия и аннулирование старой очереди.
3. Применить миграции, затем exact runtime. Проверить revision 0038, сохранность старых
   подписок, выключенную Крипту у существующих участников и пустой onboarding journal.
   До возобновления writers при ошибке восстановить backup и прежний exact runtime.
4. Проверить /readyz exact release и heartbeat. Это только инфраструктурная проверка.
5. Отдельно активировать webhook allowed_updates с edited_message через versioned
   telegram_features. Не удалять ожидающие обновления.
6. По согласованному пользовательскому сценарию включить simplified через аудитируемый
   интерфейс или `python -m community_bot.bootstrap.registration_policy` (dry-run,
   затем --apply). CLI требует единственного активного суперадминистратора и использует
   существующий set_policy с проверкой revision. Сам cutover режим не переключает.
7. Обновление клавиатуры существующим пользователям — отдельная внешняя рассылка:
   telegram_menu_refresh, campaign activity-center-v2, сначала dry-run и проверка receipts,
   затем согласованный apply. Повторный запуск не должен рассылать повторно.
8. Проверить реальный вход через @humanquest_bot с настоящим initData: Start, членство,
   новый профиль без анкеты, меню, подписка/отписка и разрешённая тестовая публикация.
   Без доступной Telegram-сессии явно отметить отсутствие production Telegram acceptance.

После открытия writers нельзя откатывать БД старым backup без отдельного решения о новых
данных. Downgrade SQL консервативно объединяет task-подписки, но не заменяет cutover rollback.
