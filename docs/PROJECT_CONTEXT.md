# Контекст проекта

## Цель

Проверить повторяемый цикл взаимной помощи в закрытом сообществе:

```text
регистрация → задание → выполнение → проверка
→ кредиты и опыт → репутация → повторное участие
```

Пользователь работает через Telegram Mini App. Telegram используется как платформа запуска и идентификации, а также для коротких уведомлений.

## Подтверждённые решения

- Существующая доменная и прикладная логика, PostgreSQL, ledger, audit, outbox, worker и миграции сохраняются.
- Старый Telegram chat UI, long polling и R1 pilot/release больше не являются частью продукта.
- Mini App и будущий browser mode используют один versioned HTTPS API и один backend.
- Сервер повторно проверяет role/status/permissions/ownership для защищённых операций.
- Jira `CB` хранит задачи и критерии, Git — долговременные решения, MemPalace — только несекретный поисковый индекс.
- Русский язык каноничен для смысловой документации и Jira.

## Текущий этап

CB-62 очищает репозиторий и фиксирует Mini App-only runtime. Далее CB-51—CB-57 последовательно добавляют actor context, HTTP API, frontend, интеграцию платформы, эксплуатационный контур и acceptance.

## Открытые вопросы

- публичное название сообщества;
- политика хранения и удаления пользовательских данных;
- browser authentication вне Telegram;
- целевой hosting и rollout нового HTTPS/frontend контура.
