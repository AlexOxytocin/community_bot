# Правила и ограничения Community Bot

Обновлено: 2026-08-24. Этот документ раскрывает доменные ограничения проекта;
операционный минимум для Codex находится в корневом `AGENTS.md`.

## Источники истины

- Код и git-документация определяют фактическое поведение и долговременные
  решения.
- Jira `CB` определяет статус и критерии только уже отслеживаемых задач.

## Пропорциональный процесс

| Уровень | Когда | Минимум |
| --- | --- | --- |
| `local` | анализ, docs, tooling, маленький fix | локальная правка, целевая проверка, отчёт |
| `tracked` | дан Jira-ключ или запрошен PR | задача, нужный git-маршрут, проверки критериев |
| `release` | production, миграция, security, необратимый риск | план отката, необходимые integration/smoke, внешняя проверка |

Jira, task branch, PR, независимый review, E2E и отдельные отчётные файлы не
являются универсальными gates. Каждый из них включается только своим уровнем,
явным запросом или конкретным риском.

## Архитектура

- Для первой версии сохраняется небольшой модульный монолит с явными границами
  transport, application, domain и infrastructure.
- Детерминированные проверки, права и вычисления реализуются кодом. LLM
  применяется только для задач естественного языка или реальной неоднозначности.
- ADR нужен для долговременного структурного решения, а не для обычной правки.
- Не разрешать продуктовый `TBD` молча в коде: сначала зафиксировать решение.

## Качество

- Проверка покрывает изменённое поведение и ближайший риск регрессии.
- Integration-тест нужен при изменении интеграционной границы; E2E — при
  изменении критического пользовательского пути; полный regression — перед
  соответствующим release, а не после каждой задачи.
- Процент покрытия сам по себе не является gate без отдельного требования.
- После изменения, затрагивающего поведение, обновляется только релевантная
  документация.

## Внешние операции

- Создание/изменение Jira, push, PR, merge, deployment и отправка сообщений
  выполняются только при ясном намерении пользователя.
- Перед повтором внешней операции проверяется фактическое состояние.
- Нельзя сообщать о deployment до проверки новой версии на публичном URL.

## Telegram и данные

- Пользовательские Telegram-операции идут через глобальный wrapper и отдельные
  правила `C:\Users\User\.codex\rules\telegram.md`.
- Старый Telegram chat UI и long-polling bot runtime не восстанавливаются.
- Telegram используется для Mini App auth/deep link и коротких уведомлений в
  пределах актуального продукта.
- Секреты, sessions, cookies, OTP и приватные чаты не сохраняются в git, Jira,
  документации или task artifacts.

## Устаревший контур

Проектная система `community_bot.orchestration.v2`, каталог `agents/`,
обязательный Jira-first, обязательный Ponytail и универсальный final-review
выведены из эксплуатации 2026-08-24. Они не являются источниками инструкций.
