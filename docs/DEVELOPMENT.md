# Локальная разработка

## Первый запуск

Требуются uv 0.12.3, Python 3.13 и Docker Compose.

```powershell
.\scripts\dev.ps1
```

Скрипт синхронизирует зависимости, запускает PostgreSQL, применяет Alembic и
запускает `community-web` на `http://localhost:8000`. Повторный запуск можно
ускорить флагом `-SkipSync`.

## Проверка

Для обычной правки передаются конкретные pytest-файлы:

```powershell
.\scripts\check.ps1 tests/unit/test_web_auth.py
```

Без аргументов выполняются быстрые unit и smoke tests. Полный локальный gate
запускается только по необходимости:

```powershell
.\scripts\check.ps1 -Full
```

Browser и PostgreSQL integration tests добавляются, когда изменение затрагивает
соответствующую границу. Coverage-порог применяется только при явном полном
coverage-прогоне.

## Правила integration-тестов

Integration-тест нужен только тогда, когда проверяемый результат зависит от
реального поведения PostgreSQL и не может быть достоверно доказан unit-тестом.
Допустимые причины:

- атомарность commit/rollback нескольких записей;
- конкурентная запись, row lock, deadlock order или `SKIP LOCKED`;
- `UNIQUE`, `CHECK`, foreign key, trigger и append-only защита;
- фактическая семантика SQL-запроса, сортировки, cursor pagination или JSONB;
- сохранение после нового подключения или restart объекта `Database`;
- upgrade/downgrade либо data backfill конкретной Alembic-миграции.

Не являются причиной для integration-теста:

- валидация входных значений и граничные числа;
- матрица ролей, статусов и permissions, если решение принимает domain или
  application-код;
- сериализация DTO, HTTP status mapping и форма ошибки;
- обычный happy path, уже доказанный другим DB-backed вертикальным сценарием;
- повторная проверка идемпотентности в каждом слое;
- запуск `SELECT 1`, проверка существования entrypoint или импортов.

### Структура suite

1. Обычные тесты получают `database_url` из `tests/integration/conftest.py`.
   Fixture один раз применяет Alembic к template-БД и создаёт из неё отдельный
   клон для каждого теста. Самостоятельный Testcontainers, Compose и повторный
   `alembic upgrade head` внутри тестовых файлов запрещены.
2. Один тест доказывает один основной DB-инвариант. Несколько бизнес-шагов
   допустимы только как подготовка этого инварианта.
3. Для вертикального среза сохраняется один канонический DB-backed happy path.
   Domain/application/Web API/browser не должны четыре раза доказывать одну
   транзакцию.
4. Комбинаторные role/status/input-матрицы остаются unit-тестами. В integration
   допускаются только варианты, меняющие SQL constraint, lock или транзакцию.
5. Migration cycle проверяется централизованно. Отдельная миграция получает
   собственный тест только при backfill, преобразовании или необратимом guard.
6. Общие builders размещаются в `conftest.py` или модуле поддержки без имени
   `test_*.py`. Существующие импорты из `test_task_creation.py` и
   `test_reputation.py` — долг, который не расширяется.
7. Новый integration-тест должен в описании изменения указывать уникальный
   DB-риск, которого нет в сохранённых сценариях. Если такого риска нет, тест
   пишется на unit-уровне либо не добавляется.

### Бюджет

На штатной локальной машине integration-suite должен укладываться в 120 секунд,
а полный `pytest` — в 240 секунд. Это диагностический бюджет, а не повод скрывать
тесты: при превышении сначала измеряются `--durations`, повторная подготовка БД,
дубли и лишняя параметризация. Текущая контрольная точка после очистки: 102
integration-теста примерно за 94 секунды и 553 теста примерно за 180 секунд.

Перед добавлением integration-теста выполни:

```powershell
uv run pytest --collect-only -q tests/integration
uv run pytest -q tests/integration --durations=15
```

## База данных

- Новая schema-правка получает новую Alembic-миграцию; историю не переписывать.
- На локальной базе допустим обычный `alembic upgrade head`.
- Миграция реальных данных всегда относится к уровню `release` и требует backup
  и rollback-плана.

## Граница с MySite

Bot backend, Mini App frontend и миграции развиваются в этом репозитории как
один продукт. `MySite` остаётся отдельным публичным/маркетинговым сайтом и может
содержать ссылку или маршрутизацию `app.godmodetools.com`, но его тяжёлый
визуальный и release-контур не является gate локальной разработки Mini App.
