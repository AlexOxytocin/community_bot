# ADR-0007 — Соразмерный цикл задач, ревью и регрессии MVP

**Статус:** Принято

**Дата:** 2026-08-10

## Контекст

Процесс начал тратить больше времени на повторные проверки узких слайсов, чем
на разработку MVP. Полная регрессия после каждой задачи особенно невыгодна:
замечание последующего review заставляет повторять её целиком.

## Решение

- Формировать более крупные задачи вокруг законченного наблюдаемого результата,
  не дробя его слои, тесты и документацию на микрозадачи.
- Plan review проводить один раз и только для задач уровня 3 на полном плане.
- До final review готовой задачи выполнять только целевые, необходимые
  интеграционные и smoke-проверки её области.
- Final review проводить на полностью готовом коде до общей регрессии продукта.
- После первого непройденного review закрывать весь пакет замечаний одним
  циклом. После второго сохранять обе попытки, создавать
  `problem-escalation.md` и выполнять одно консолидированное исправление. Новый
  непройденный review после него требует решения владельца.
- Полную регрессию проводить отдельной большой задачей после готовности всего
  запланированного функционала MVP.
- Баги, впервые найденные на общей регрессии, вести отдельными Jira-багами и
  ветками. Дефекты, найденные раньше, исправлять в текущей задаче.
- Ориентир накладных расходов на планирование, проверки и review обычной задачи
  — не более 25% её цикла.

## Размер задачи

Одна задача объединяет части одного наблюдаемого результата с конечной областью
и общей приёмкой. Независимые результаты остаются отдельными задачами под
эпиком. Небольшие задачи допустимы для самостоятельных блокеров,
инфраструктурных результатов с собственной приёмкой и багов общей регрессии.
Уровень 1 ADR-0004 сохраняет короткий путь для действительно малых правок.

## Последствия

- Проверок становится меньше, но они выполняются на более полном результате.
- Ошибки review исправляются до дорогой общей регрессии.
- Общая регрессия проверяет уже собранный MVP, а не каждый промежуточный шаг.
- История двух непройденных review хранится простыми Markdown-файлами задачи;
  отдельная процессная система для этого MVP не создаётся.
