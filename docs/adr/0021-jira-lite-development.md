# ADR-0021 — Jira-lite для текущей разработки

**Статус:** Принято

**Дата:** 2026-08-24

## Контекст

Community Mini App разрабатывается одним владельцем и пока не имеет обычного
production-релизного цикла. Обязательная цепочка Jira → branch → PR → review →
merge → deploy, набор отдельных task-отчётов и одинаковые проверки для каждого
изменения стали дороже самой разработки. При этом Jira остаётся полезной как
план и долговременная фиксация результата.

## Решение

1. Jira обязательна для значимого бага, функции, истории, runtime-, workflow- и
   process-изменения. Мелкие части существующей работы не дробятся на задачи.
2. Основной режим — `tracked`: задача, критерии, реализация, затронутая проверка
   и один итоговый комментарий.
3. Наличие Jira-задачи не требует автоматически отдельной ветки, commit, push,
   PR, независимого review, merge или deployment.
4. `local` покрывает анализ, прототип и малые неповеденческие изменения.
5. `release` покрывает production, миграцию реальных данных, security, платежи и
   другие высокорисковые внешние изменения; прежние safety/rollback контракты
   читаются заново только в этом режиме.
6. Push в `main` не разворачивает dev server автоматически. Сохранённый deploy
   workflow запускается вручную как отдельное delivery-событие.
7. Планы и evidence завершённых задач остаются в Jira и истории Git; старые ADR
   сохраняются как история, но не являются активными инструкциями.

## Последствия

- Планирование и результат остаются видимыми в Jira без терминальной стенограммы.
- Локальное изменение может завершиться без branch/PR/deploy, если пользователь
  их не запросил и риск не требует их.
- CI на PR остаётся доступным, но локальная targeted-проверка является обычным
  gate текущей разработки.
- Production-контур не удалён; перед его применением нужна отдельная release-задача
  и проверка актуальности исторических runbooks.

## Заменённые решения

Этот ADR заменяет процессные требования ADR-0004, ADR-0007 и ADR-0010, а также
универсальный post-task delivery gate ADR-0019 и automatic-on-push часть
ADR-0020. Технические правила защиты данных, миграций и rollback из release ADR
сохраняются для явного release-сценария.
