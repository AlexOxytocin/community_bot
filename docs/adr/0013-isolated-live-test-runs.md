# ADR-0013 — Изолированные live test runs в рабочем экземпляре

**Статус:** Принято

**Дата:** 2026-08-14

**Принято владельцем:** 2026-08-14. До начала реальной эксплуатации рабочий
экземпляр разрешено использовать для полных smoke-сценариев с созданием,
принятием, подтверждением, отменой и закрытием тестовых карточек.

## Контекст

Отдельная тестовая БД не подтверждает работу фактически задеплоенного Telegram-
бота. При этом обычная тестовая публикация в текущей модели попадала в общий
каталог и создавала уведомления всем active-участникам. Текстовый префикс в
заголовке не является границей доступа.

## Решение

1. Live smoke выполняется внутри отдельного `test_run` с обязательным маркером
   `TEST-*` и закрытым списком участников.
2. Пока участник находится в active test run, он видит только карточки этого
   запуска. Пользователь вне запуска видит только обычные карточки.
3. Черновик и опубликованный task сохраняют `test_run_id`. Telegram-карточка
   получает явный заголовок `ТЕСТ`.
4. Уведомления тестовой публикации адресуются только active-участникам этого
   запуска. Участники запуска временно исключаются из широких уведомлений
   обычных публикаций.
5. Прямое принятие по известному UUID повторно проверяет совпадение test scope;
   фильтра каталога недостаточно для авторизации.
6. Незавершённый черновик удаляется штатной отменой. Опубликованная карточка и
   назначения приводятся в терминальное состояние штатными командами. После
   завершения запуска карточки исчезают из рабочих представлений, но аудит и
   экономический ledger физически не удаляются.
7. `finish` работает fail-closed и отклоняется при наличии незавершённых
   черновиков, tasks или assignments.
8. Факты, связанные с тестовыми tasks и assignments, исключаются из пилотных
   продуктовых метрик.
9. Управление scope выполняется Python entrypoints `community-test-run` и
   `ops/smoke_production.py`; Telegram ID не выводятся в отчёты.

## Последствия

- Smoke может проходить полные живые сценарии на реально задеплоенном runtime и
  production schema, не показывая тестовые карточки посторонним пользователям.
- История теста остаётся расследуемой; «очистка» означает доменное завершение и
  удаление из рабочих поверхностей, а не повреждение immutable журналов.
- Перед началом реальной эксплуатации владелец обязан пересмотреть этот режим:
  перенести полный E2E в отдельного тестового бота либо явно сохранить только
  минимальный production smoke.
