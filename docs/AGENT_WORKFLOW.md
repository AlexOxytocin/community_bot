# Рабочий процесс Codex

Обновлено: 2026-08-24.

## 1. Определить результат

Сформулировать наблюдаемый результат, область изменения и проверку. Сначала
прочитать корневой `AGENTS.md`, затем только документы, которые действительно
относятся к задаче.

## 2. Выбрать уровень

- `local` используется для анализа, прототипа и совсем малых неповеденческих
  изменений.
- `tracked` используется по умолчанию для значимых багов, функций, историй,
  runtime- и process-изменений. Если ключ не дан, сначала ищется подходящая
  открытая задача Jira, а при её отсутствии создаётся новая.
- `release` используется для production, миграций, security и необратимых
  операций.

Не повышать уровень «на всякий случай».

## 3. Исследовать ровно необходимое

Найти фактический путь выполнения и существующие тесты. Не загружать весь
документальный корпус и не создавать многоагентную карту репозитория без прямого
запроса пользователя.

## 4. Изменить минимально

Сохранить несвязанные правки, действующие контракты и стиль соседнего кода.
Новая абстракция добавляется только при наличии текущей, а не гипотетической,
повторяемости или границы.

## 5. Проверить пропорционально

- Всегда: целевая проверка изменённого поведения.
- При интеграционной границе: релевантный integration-test.
- При критическом пользовательском пути: соответствующий smoke/E2E.
- При release: согласованный release checklist и rollback proof.

Полный regression, независимый review и формальный test report не запускаются
для local- или обычной tracked-задачи автоматически. Наличие Jira-задачи не
является основанием для ветки, PR или deployment.

## 6. Передать результат

Сообщить:

1. что изменено;
2. чем проверено;
3. какой риск остался;
4. какие внешние действия не выполнялись.

Для tracked/release добавить в Jira один содержательный итог: что сделано, чем
проверено и какой риск остался. Отдельно указать фактические git/deploy действия.
Не считать локальный результат публичным delivery.

## Субагенты

Проект не требует субагентов. Они запускаются только по прямому запросу
пользователя для независимых параллельных частей. Один агент не порождает
дочерних агентов по умолчанию и не передаёт им полную историю без необходимости.
