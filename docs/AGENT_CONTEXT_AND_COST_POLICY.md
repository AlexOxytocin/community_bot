# Контекст и стоимость агентской работы

## Назначение

Этот документ задаёт границу между глобальными execution budgets Codex и
проектной оркестрацией Community Bot. Он сохраняет полноценную многопоточную
разработку, но не разрешает каждой роли заново загружать весь проект или
создавать собственные лимиты.

## Источники истины

- `codex.agent-budget.v1` в
  `windows_user_profile/.codex/policies/agent-budget.yaml` — единственный исполняемый
  источник моделей, reasoning effort, concurrency, follow-up, polling,
  checkpoint, hard limit, extension и fresh-context handoff;
- `community_bot.orchestration.v2` в `agents/config.yaml` — единственный
  источник проектной маршрутизации документов и ролей, process/review limits,
  форматов компактных пакетов и ограничений вывода инструментов;
- `agents/workflow.yaml` только ссылается на эти контракты и не копирует их
  значения.

Если глобальная политика недоступна, нельзя придумывать запасные числовые
лимиты. Следует вернуть blocker либо выполнить работу без делегирования в
рамках уже действующих инструкций корневого агента.

`windows_user_profile` разрешается через
`[Environment]::GetFolderPath('UserProfile')`. Команда validation в
`agents/config.yaml` выполняет это разрешение сама и не требует ручной
подстановки placeholder.

## Загрузка контекста

Стартовый набор состоит из `AGENTS.md` и
`docs/PROJECT_RULES_AND_GUARDRAILS_RU.md`. Дальше подключается только маршрут,
соответствующий фактической задаче: Jira/process, product, domain,
technology/architecture, multi-agent, Telegram/live или release/deployment.
Полный перечень находится в
`agents/config.yaml#/orchestration_policy/document_routing`.

Роль получает ссылки на релевантные файлы, а не полную историю диалога. Если
источник велик, владелец контекста передаёт краткий вывод, точный путь и
достаточный фрагмент для проверки утверждения.

## Выбор роли

Карта project role → global profile хранится только в
`agents/config.yaml#/orchestration_policy/role_routing`. Luna используется для
ограниченной разведки и механических слайсов с ясной приёмкой. Сложная
реализация и независимые смысловые проверки остаются за Sol. Повышение роли
происходит по условиям карты, а не просто из-за длины задачи.

Каждый дочерний агент получает один ограниченный результат с владельцем файлов
и проверкой готовности. Независимые слайсы можно выполнять параллельно; общий
файл, неразделённый контракт или последовательная зависимость требуют одного
владельца либо явного порядка.

## Компактные пакеты

Форматы task, review и Jira snapshot определены в
`agents/config.yaml#/orchestration_policy/packets`. Пакет должен содержать
проверяемые факты, текущий diff/результат, ссылки на источники, остаточный риск
и точное следующее действие. Полная стенограмма, повторные дампы Jira и
нерелевантные документы в пакет не входят.

Review проверяет фактический diff и доказательства, поэтому краткость пакета не
заменяет доступ к исходным файлам. Большой вывод инструмента сохраняется в
файл; в контекст передаются путь, итог и релевантный фрагмент согласно
`tool_output`.

## Продолжение и ожидание

Конечный граф, progress evidence и исполняемые пределы продолжения определены
только в `codex.agent-budget.v1`. Раздел
`agents/config.yaml#/orchestration_policy/continuation` хранит точные ссылки на
этот контракт и формат handoff packet, не копируя граф или его условия.

При исчерпании текущего контекста работа не начинается заново: создаётся task
packet и, если глобальная политика разрешает, выполняется fresh-context
handoff. Неизменное внешнее состояние не опрашивается бесконечно; после
допустимых проверок используется событийное ожидание либо фиксируется blocker.

## Проверка

Глобальная согласованность проверяется командой из
`external_execution_policy.validation_command`. Репозиторный тест проверяет
маршруты, точные global refs, bounded project budgets, существование
consumer-файлов и отсутствие локальных копий execution budgets. Конечность
canonical graph проверяет global validator.
