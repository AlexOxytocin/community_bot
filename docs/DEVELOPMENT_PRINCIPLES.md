# Принципы разработки

1. **Один небольшой продукт.** Сохранять модульный монолит, одну PostgreSQL и
   один web-клиент. Не добавлять микросервисы, broker, CQRS, Kubernetes или
   универсальный framework без измеренной проблемы.
2. **Jira для плана, Git для знания.** Значимая работа отслеживается в Jira;
   архитектура, ADR и эксплуатационные контракты версионируются рядом с кодом.
3. **Вертикальные срезы.** Задача должна давать наблюдаемый результат целиком,
   а не отдельный слой API, БД или UI без пользовательской ценности.
4. **Backend владеет правилами.** Web UI не вычисляет права, допустимые переходы,
   награды или статусы и не создаёт второй источник бизнес-состояния.
5. **Детерминированное — кодом.** LLM не используется там, где достаточно
   валидации, схемы, запроса или обычного алгоритма.
6. **Идемпотентность внешних эффектов.** Telegram, ledger, audit и outbox не
   должны получать дубль при повторе операции.
7. **Минимальная правка.** Новая абстракция появляется из текущей повторяемости,
   а не из предположения о будущем масштабе.
8. **Пропорциональная проверка.** Всегда проверяется затронутое поведение;
   integration, browser/E2E, полный regression и независимый review добавляются
   по риску, а не по факту наличия Jira-задачи.
9. **ADR только для долговременного решения.** Рутинная реализация и временный
   план остаются в Jira, а не создают новый документ.
10. **Production — отдельное событие.** Deployment, миграция реальных данных и
    rollback выполняются только как явная release-работа.
11. **Integration доказывает инфраструктуру.** Реальная PostgreSQL используется
    для транзакций, конкуренции, SQL, constraints и миграций; бизнес-матрицы и
    transport-ветвление остаются быстрыми unit-тестами. Повторная миграция БД и
    дубли одного вертикального пути считаются дефектом тестового кода.
