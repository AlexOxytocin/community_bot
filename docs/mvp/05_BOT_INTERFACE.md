# Интерфейс Telegram-бота

## 1. Общие принципы

- Основная навигация выполняется через inline-кнопки и главное меню.
- Команды остаются резервным способом навигации.
- Каждое опасное или необратимое действие требует подтверждения.
- Длинные списки используют пагинацию.
- После ошибки пользователь получает понятный следующий шаг, а не технический текст.
- Сообщения не являются источником истины: состояние хранится в базе.

## 2. Команды

```text
/start          регистрация или главное меню
/profile        моя карточка
/tasks          доступные задания
/create         создать задание
/my_tasks       мои задания
/balance        кредиты и операции
/stats          статистика
/leaderboard    лидерборд
/help           правила и поддержка
/cancel         отменить текущий диалог
```

Административные команды доступны только соответствующим ролям:

```text
/admin
/registrations
/disputes
/catalog
/community_tasks
/interaction_alerts
/product_config
/audit
/catalog [category_code] [online|offline]
/catalog_category <code> <on|off>
/catalog_template <code> <on|off>
/catalog_template_reward <code> <1..4>
/invite_create [лимит] [дни] [telegram_id]
/invite_revoke <invitation_id>
/registration_reject <member_id> <причина>
```

На текущем программном интерфейсе создания доступны резервные команды:

```text
/task_create [template_id]  продолжить текущий или создать новый черновик
/task_resume <draft_id>     открыть сохранённый черновик
/task_preview               проверить карточку перед публикацией
/task_cancel <draft_or_task_id>
                            удалить черновик или отменить своё задание
/my_assignments             мои принятые задания и их состояния
/assignment_cancel <assignment_id> <причина>
                            освободить слот до отправки результата
/assignment_submit <assignment_id>
                            начать или возобновить сохраняемый ввод результата
/assignment_result <draft_id> <revision> <result_json>
                            сохранить предпросмотр перед подтверждением callback
/assignment_dispute <assignment_id> <комментарий>
                            открыть приватный спор в доступном окне
```

Кнопка принятия использует callback `task:accept:<task_id>`. Решение автора
передаётся callback `assign:review:<assignment_id>:full|partial|reject`.
Черновик, его revision и стабильный идентификатор отправки хранятся в
PostgreSQL, поэтому callback работает после перезапуска процесса. Повтор одного
Telegram update возвращает сохранённый результат без второй выплаты, версии,
outbox-события или receipt.

## 3. Главное меню

```text
[ Найти задание ]   [ Создать задание ]
[ Мои задания ]     [ Моя карточка ]
[ Статистика ]      [ Лидерборд ]
[ Участники ]       [ Правила ]
```

Пункт `Участники` и переходы к чужим карточкам показывают только профили, доступные по правилу видимости. Само правило остаётся `Q-011` и не задаётся макетом меню.

## 4. Карточка задания в списке

```text
PRODUCT-1042 · Тест первых десяти минут

Категория: Тестирование продукта
Автор: Сообщество
Награда: 2 кредита
Срок: 18 августа, 19:00
Формат: онлайн
Уровень: от 2

[ Подробнее ] [ Взять ]
```

## 5. Подробная карточка задания

Должна показывать:

- автора; для `origin=community` всегда показывается «Сообщество»;
- шаблон и категорию;
- ожидаемое действие;
- критерий завершения;
- предоставленные материалы;
- срок;
- награду;
- ограничения;
- количество мест;
- статус.

## 6. Карточка участника

Карточка ниже отображается только после серверной проверки права просмотра; круг доступных профилей определяется решением `Q-011`.

```text
Имя
Город · часовой пояс

Краткое описание
Текущая цель

Может помочь:
• категория
• навык

Уровень: 4 · Уверенный вклад
Опыт: 86
Карма: +7 · 13 оценок
Надёжность: 89%
Выполнено заданий: 31
```

Название и порог берутся из активной версии продуктовой конфигурации. Интерфейс
не хранит собственную копию шкалы и не принимает решения по устаревшему кэшу.

Чужой баланс кредитов не отображается.

Кнопки:

```text
[ Задания участника ] [ Оценить карму ]
[ Назад ]
```

## 7. Собственная карточка

Дополнительно показывает:

- баланс кредитов;
- прогресс до следующего уровня;
- место в лидерборде;
- активные задания;
- историю операций;
- кнопку редактирования.

## 8. Лидерборд

```text
Лидерборд по опыту

1. Анна — 347 опыта
2. Михаил — 291 опыта
3. Марина — 238 опыта
...

Ваше место: 12
Ваш опыт: 86
```

Текущий баланс кредитов и карма не используются для сортировки.

## 9. Уведомления

Обязательные события:

- регистрация подтверждена или отклонена;
- опубликовано подходящее задание, если включена подписка;
- задание принято;
- приближается срок;
- исполнитель отправил результат;
- автор подтвердил или отклонил результат;
- проверяющему результата отправлены напоминания через 24 и 48 часов;
- результат автоподтверждён на границе 72 часов;
- после отклонения открыт или истёк отдельный 24-часовой срок спора;
- заданию сообщества требуется новый независимый проверяющий;
- начислены кредиты и опыт;
- открыт или решён спор;
- изменился уровень;
- изменён административный статус.

Напоминания о сроке должны быть конфигурируемыми. Предварительно: за 24 часа и за 2 часа.

Административный алерт повторяющихся взаимодействий не отправляется участникам.
В приватной очереди администратор с правом `interaction_review` видит пару,
счётчик, окно, связанные оплаченные выполнения и версии политики. Закрытые
заметки встречи не отображаются в пользовательских карточках и уведомлениях.

## 10. Состояния диалога

Диалоги регистрации, создания задания, отправки результата и кармы должны быть возобновляемыми после перезапуска.

Каждое состояние хранит:

```text
member_id
flow_type
current_step
payload_json
expires_at
updated_at
```

Каждое изменяющее сообщение содержит ожидаемый шаг прикладной команды. Сервер
сначала сериализует update и Telegram user ID, затем повторно читает состояние:
запоздавший ответ на предыдущий вопрос не применяется к следующему полю.

Просроченный черновик можно восстановить или удалить по выбору пользователя.
Для создания задания хранится отдельная типизированная строка черновика с
точной версией шаблона, шагом, revision и стабильным publish command ID.
Callback публикации содержит UUID черновика и revision, укладывается в лимит
Telegram 64 байта и безопасно повторяется после перезапуска.
