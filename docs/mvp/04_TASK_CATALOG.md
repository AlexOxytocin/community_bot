# Категории и каталог заданий

## 1. Принцип MVP

Обычный участник создаёт задание без выбора шаблона. Он последовательно выбирает
тип задания, категорию, размер по времени, число исполнителей, награду за одного
исполнителя, описание, критерии приёмки и материалы. Шаблонный каталог остаётся
для исторических карточек, резервных команд и административных сценариев
заданий сообщества.

Активный администратор со специальным правом может создать задание с
`origin=community` через административный поток. Это контролируемое исключение
для развития сообщества, привлечения аудитории и создания новой ценности; оно не
отменяет требования к ограниченному объёму, проверяемому результату,
добровольности и безопасности.

Это обеспечивает:

- предсказуемый объём;
- понятную шкалу времени и награды;
- проверяемый результат;
- более простую модерацию;
- сопоставимую статистику.

## 2. Поля категории

```text
id
code
name
description
icon
sort_order
visibility: public | admin_only
creation_mode: template | freeform | both
is_active
```

Категории хранятся в PostgreSQL как рабочий справочник. Для создания свободных
заданий показываются только active-категории с `creation_mode=freeform|both`;
категория `admin_only` видна только active administrator.

## 3. Категории свободного создания

Inline-меню создания показывает:

- `📣 Продвижение`;
- `🔍 Оценка и тестирование`;
- `💬 Коммуникация`;
- `🎓 Обучение и разбор`;
- `🤝 Практическая помощь`;
- `🧩 Другое`;
- `🌱 Развитие комьюнити` — только для active administrator.

`Другое` является fallback-категорией, когда задача не ложится в основные
пункты. Административная категория не должна появляться в меню обычного
участника.

## 4. Шаблонные категории v1

Миграционный seed v1 содержит восемь шаблонных категорий ниже и по одному
безопасному пилотному шаблону из первой позиции каждой категории. Полный
неизменяемый снимок с инструкциями, критериями и JSON Schema хранится в
`migrations/data/task_catalog_v1.json`. Остальные перечисления являются очередью
расширения шаблонного каталога и добавляются новыми версиями/миграциями, а не
изменением опубликованного seed.

### Разработка и GitHub (`development`)

- первое впечатление от репозитория;
- проверка README;
- чистая установка;
- воспроизведение issue;
- тестирование релиза;
- ограниченное код-ревью;
- небольшой contribution.

### Тестирование продукта (`product_testing`)

- регистрация с записью экрана;
- первые десять минут;
- прохождение сценария;
- поиск проблем интерфейса;
- мобильная проверка;
- сравнение с конкурентом;
- пользовательское интервью.

### Карьера (`career`)

- проверка резюме;
- аудит портфолио;
- мок-собеседование;
- техническое интервью;
- переговоры о зарплате;
- проверка тестового задания;
- проверка самопрезентации.

### Контент и продвижение (`content_marketing`)

- проверка лендинга;
- оценка оффера;
- тест заголовков;
- редактура текста;
- поиск площадок;
- интервью потенциального клиента.

### Связи и репутация (`networking`)

- аудит LinkedIn;
- проверка навыка;
- endorsement после проверки;
- профессиональная рекомендация при наличии реального опыта;
- тёплое знакомство с согласием сторон;
- поиск релевантных контактов.

### Обучение (`learning`)

- практическая консультация;
- объяснение инструмента;
- проверка задания;
- разговорная практика;
- подбор материалов;
- контрольная проверка навыка.

### Продуктивность (`accountability`)

- совместная рабочая сессия;
- трёхдневный контроль обязательства;
- декомпозиция задачи;
- планирование недели;
- повторная проверка результата.

### Социальная и практическая помощь (`social_help`)

- ограниченный поддерживающий разговор;
- совместное посещение мероприятия;
- знакомство внутри сообщества;
- организация небольшой встречи;
- навигация по городу;
- сопровождение;
- ограниченная бытовая помощь.

## 6. Требования к каждой карточке и шаблону

Карточка свободного задания или шаблон допускается к публикации, только если:

1. Результат можно проверить.
2. Объём ограничен.
3. Есть ожидаемое время выполнения.
4. Награда соответствует объёму.
5. Исполнитель может отказаться без внешнего давления.
6. Публичная реакция не предопределена заказчиком.
7. Задание не требует нарушения правил внешней платформы.

## 7. Публичные сигналы

Нельзя выдавать награду только за обязательный лайк, звезду, подписку, положительный отзыв или endorsement.

Допустимая карточка:

```text
Изучить репозиторий и дать структурированный отзыв.
Звезда ставится только при искреннем интересе.
Честный отказ поставить звезду не лишает исполнителя награды.
```

Аналогично для LinkedIn и публичных отзывов: оплачивается проверка и достоверная обратная связь, а не заранее заданный положительный сигнал.

## 8. Размер и стоимость свободного задания

Пользователь выбирает размер кнопкой:

```text
⚡ XS  до 15 минут       1 или 2 кредита
⭐ S   15–40 минут       2, 3 или 4 кредита
💎 M   40–75 минут       4, 5, 6 или 7 кредитов
🏆 L   75–120 минут      6, 7, 8, 9 или 10 кредитов
👑 XL  больше 120 минут  любое целое число больше 10
```

Награда задаётся за одного исполнителя. Для группового задания полный резерв
считается как `reward_per_performer * performer_slots`; число исполнителей
должно быть положительным целым числом, а для группового задания — больше `1`.
Публикация запрещается, если доступных кредитов автора не хватает на полный
резерв.

## 9. Ограничения против фарминга

- Жёсткого лимита на число оплаченных взаимодействий пары нет: превышение
  конфигурируемого порога не блокирует принятие, публикацию или оплату задания.
- Пилот создаёт приватный административный алерт на четвёртом полном или
  частичном оплаченном взаимодействии неупорядоченной пары за скользящие `7`
  суток. Порог `3` и окно `7` суток входят в версионируемую продуктовую
  конфигурацию; `0` отключает новые алерты.
- Задания сообщества не входят в счётчик пары. Открытый алерт только обновляется,
  а не дублируется; штраф возможен лишь после встречи и ручного исхода
  `penalty_recommended`.
- Один автор не может одновременно публиковать несколько идентичных карточек.
- Нельзя создавать задание для заранее выбранного исполнителя в обход общего каталога.
- Удалённые или деактивированные шаблоны сохраняются для истории.
- Изменение стоимости шаблона создаёт новую версию и не влияет на уже опубликованные задания.

В каждый момент активна не более одна версия одного `code`. Отключение скрывает
шаблон из новых публикаций, но не удаляет его строку и не ломает ссылку уже
созданного задания. Каталог использует keyset по неизменяемой логической позиции
`(category.sort_order, template.code)`, поэтому новая версия уже показанного
шаблона не появляется повторно на следующей странице. `category_id` является
частью логической идентичности `template.code` и не может меняться между версиями.

## 10. Карточка задания сообщества

Неизменяемый снимок карточки содержит:

```text
origin: community
category_id
title
description
completion_criteria
format
materials
deadline_at
maximum_performers
estimated_minutes
minimum_level
credit_reward
reviewer_admin_id
safety_confirmation
```

Отображаемый автор — «Сообщество». Время не превышает `120` минут. Награда
`1–4` соответствует обычной шкале стоимости; большее значение требует
обоснования, второго явного подтверждения администратора и аудита. При создании
назначается независимый проверяющий, который не является исполнителем ни одного
слота.

Нельзя требовать обязательный лайк, подписку, положительный отзыв, endorsement,
публичное одобрение или нарушение правил внешней платформы. Задание должно быть
добровольным, ограниченным и проверяемым ровно так же, как шаблон участника.
