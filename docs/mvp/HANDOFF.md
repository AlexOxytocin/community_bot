# Handoff после переноса в `community_bot`

## Текущее состояние

Пакет продуктовой и технической документации MVP закрытого сообщества взаимной
помощи хранится в `docs/mvp`, а Jira `CB` определяет текущую очередь разработки.

Зафиксированы:

- назначение и границы MVP;
- кредиты, опыт, карма, уровни и надёжность;
- роли, пользовательские сценарии и интерфейс бота;
- категории и фиксированные шаблоны заданий;
- модель данных, безопасность, модерация и защита от накрутки;
- этапы реализации и план тестирования;
- технологический стек в [TECH_STACK.md](TECH_STACK.md) и [ADR-0005](../adr/0005-mvp-technology-stack.md);
- рабочий каркас Python 3.13, PostgreSQL 18, миграции, CI, модульные границы,
  фундамент участников, авторизации, аудита и защиты от повторных Telegram updates.

Технический каркас и фундамент участников уже реализованы. Следующая работа
выбирается только по готовой и разблокированной Jira-задаче, а не по старому
порядку первоначального bootstrap.

## Инструкция для следующей задачи

1. Прочитать `AGENTS.md`, канонические документы MVP и актуальную Jira-задачу.
2. Проверить зависимости и реальные статусы связанных задач через Atlassian API.
3. Работать в отдельной ветке `task/<ISSUE-KEY>` по одобренному плану.
4. Не реализовывать соседние этапы и не разрешать открытые вопросы молча.
5. Выполнить полный локальный контур с PostgreSQL без пропущенных тестов,
   независимый final review, PR и CI до слияния.

## Реализованный технический фундамент

- `pyproject.toml` и `uv.lock` с Python 3.13, uv, Ruff, ty и pytest;
- source layout с транспортным, прикладным, доменным и инфраструктурным слоями;
- воспроизводимый запуск PostgreSQL;
- миграции фундамента и PostgreSQL 18 через Docker Compose;
- минимальные запускаемые процессы `bot` и `worker`;
- документированные команды запуска и проверки;
- GitHub Actions с быстрым quality-срезом и полным PostgreSQL-прогоном.
- принятый профиль пилота из ADR-0008: Render Pro, два image-backed процесса,
  managed PostgreSQL 18/PITR, один GHCR digest и Sentry с очищенным payload.

## Критические запреты

- не зашивать утверждённые пилотные названия и пороги уровней в код: использовать
  активную неизменяемую версию продуктовой конфигурации;
- не заменять журнал операций простым изменяемым балансом;
- не связывать карму с автоматическими наказаниями;
- не начислять опыт за стартовые кредиты и возвраты;
- не помещать бизнес-правила в Telegram handlers;
- не добавлять Redis, Celery, FastAPI, микросервисы или LLM без новой подтверждённой причины.
- не добавлять external daily backup, application object storage или webhook в
  CB-15: владелец исключил их из текущей области.

## Состояние продуктовых решений

Решения о названиях и порогах уровней, стартовом гранте, истечении, проверке,
частичной оплате, алертах повторяющихся взаимодействий, заданиях сообщества,
допуске к карме, видимости комментариев и профилей приняты 2026-08-10. Политика
модерации, исходов спора, одной апелляции и приватных risk signals, а также ниша
и эксплуатационный профиль пилота приняты 2026-08-11. Все решения перенесены в
[журнал решений](11_DECISIONS_AND_OPEN_QUESTIONS.md); открытых продуктовых
вопросов, блокирующих текущий MVP, нет.
