# Пользовательские сценарии

## 1. Регистрация

```text
/start
→ проверка Telegram ID
→ проверка приглашения
→ согласие с правилами и приватностью
→ имя
→ город; бот автоматически определяет часовой пояс, если это можно сделать однозначно
→ ближайший крупный город для определения часового пояса — только если автоматическое определение не удалось
→ краткое описание
→ текущая цель
→ категории, в которых может помогать
→ теги навыков
→ доступность
→ предварительный просмотр
→ отправка на модерацию
→ подтверждение
→ однократное начисление 10 кредитов без опыта
→ главное меню
```

Повторный `/start` продолжает незавершённую регистрацию либо открывает меню.
Если модератор отклонил анкету с объяснением, участник возвращается к
предварительному просмотру, исправляет поля и повторно отправляет ту же заявку.
Новый аккаунт и второй стартовый грант при этом не создаются.

## 2. Просмотр заданий

```text
Главное меню
→ Найти задание
→ категории
→ фильтры: онлайн/офлайн, срок, награда, уровень
→ список карточек
→ подробности
→ Взять задание
→ подтверждение обязательства
```

Перед принятием бот показывает срок, критерий результата и последствия отказа.
Задания участников и задания с автором «Сообщество» находятся в одном каталоге;
у карточки сообщества явно показаны системный источник награды и независимый
проверяющий.

## 3. Создание задания

```text
Главное меню
→ Создать задание
→ категория
→ фиксированный шаблон
→ заполнение переменных шаблона
→ срок
→ формат
→ материалы
→ предварительный просмотр
→ проверка баланса
→ резервирование кредитов
→ публикация
```

Если баланса недостаточно, публикация запрещается без частичного резервирования.
Каждый шаг сохраняется в PostgreSQL. После перезапуска участник продолжает
текущий черновик командой `/task_create` или выбирает другой сохранённый
черновик через `/task_resume <draft-id>`. Предварительный просмотр не меняет
баланс и показывает будущую карточку с деталями автора, критерием результата и
материалами; полный резерв создаётся только одновременно с публикацией. Повторный
callback возвращает уже созданное задание без второго резерва. Исполнитель видит
тот же контекст в каталоге и сразу после принятия задания.

До появления исполнителей автор может отменить опубликованное задание командой
`/task_cancel <task-id>`: весь резерв возвращается, опыт не начисляется. Правила
отмены после принятия задания добавляются вместе с assignments.

## 4. Выполнение

```text
Мои задания
→ Я выполняю
→ выбранное выполнение
→ Отправить результат
→ текст/ссылка/файл по требованиям шаблона
→ подтверждение отправки
→ статус submitted
```

После отправки исполнитель не может незаметно заменить результат. Дополнение создаётся отдельной версией.

## 5. Подтверждение результата

```text
уведомление автору
→ открыть результат
→ Выполнено / Частично / Не выполнено / Спор
→ короткий комментарий
→ подтверждение решения
```

После полного подтверждения начисление выполняется немедленно. Изменение решения требует модератора.

Первая отправка открывает проверку на `72` часа. Автор или независимый
проверяющий получает напоминания через `24` и `48` часов. Дополнительная версия
результата не сдвигает срок; на точной границе один финализатор
автоподтверждает результат.

Отклонение открывает отдельное окно спора `24` часа и замораживает расчёт. В
этом окне исполнитель может открыть спор даже после истечения первоначальных
`72` часов. Без спора финализатор возвращает резерв автору либо закрывает
задание сообщества без выпуска награды.

## 6. Отмена

Исполнитель выбирает причину:

- не могу выполнить;
- автор изменил объём;
- автор не предоставил материалы;
- техническая проблема;
- другое.

Ранняя отмена и отмена по вине автора не считаются `no_show`. Поздняя отмена без согласования может повлиять на надёжность.

## 7. Оценка кармы

Предусловия: оба участника `active`, это не самооценка, а между парой уже была
хотя бы одна ненулевая полная или частичная выплата по заданию участника.

```text
карточка участника
→ Оценить отношение
→ +1 / 0 / -1
→ обязательный комментарий
→ сохранить
```

При повторном открытии участник видит собственную текущую оценку и может её изменить.

Получатель и moderator видят только агрегат и количество оценок. Текст,
автор, время отдельной оценки и история им не показываются. Eligibility после
первой валидной выплаты сохраняется навсегда, но изменение оценки блокируется,
если один из участников больше не `active`.

Пункт `Участники` показывает active-пользователю безопасные карточки всех
active-участников. Чужой non-active профиль не открывается ни из каталога, ни по
callback или прямому идентификатору. Собственная карточка доступна при `active`
и `paused`.

## 8. Статистика

Участник видит:

- текущий баланс кредитов;
- опыт и уровень;
- прогресс до следующего уровня;
- место в лидерборде;
- карму и количество оценок;
- надёжность;
- созданные, принятые и завершённые задания;
- уникальных участников, которым помог;
- распределение по категориям;
- историю операций.

## 9. Спор

```text
одна из сторон открывает спор
→ выбирает причину
→ добавляет объяснение и доказательства
→ задание и резерв замораживаются
→ модератор рассматривает
→ полная выплата / частичная / возврат / санкция
→ обе стороны получают решение
```

## 10. Административные сценарии

Администратор работает через отдельное меню:

- ожидающие регистрации;
- активные задания;
- просроченные задания;
- открытые споры;
- участники с ограничениями;
- категории и шаблоны;
- приглашения;
- корректировки экономики;
- сигналы подозрительной активности;
- журнал действий.

### Задание от сообщества

```text
Админка → Задания сообщества → Создать
→ категория и безопасная карточка
→ проверяемый результат, формат и материалы
→ дедлайн, слоты, время до 120 минут и минимальный уровень
→ награда 1–4 кредита
→ независимый администратор-проверяющий
→ предварительный просмотр → подтверждение → публикация в общем каталоге
```

Награда выше `4` требует обоснования и второго явного подтверждения
администратором. При полном или частичном принятии система выпускает фактическую
награду и столько же опыта. Если проверяющий стал недействителен, расчёт
останавливается в `reviewer_required`; назначение нового независимого
проверяющего открывает новое окно `72` часа с напоминаниями `24/48`.

Администратор-исполнитель не может проверять, отменять или принимать результат
этого задания. После принятия отмена возможна только до отправки результата и
только по причине сообщества или системы, с аудитом и правом обжалования.

### Алерт повторяющихся взаимодействий

```text
четвёртая оплаченная помощь одной пары за скользящие 7 суток
→ приватный алерт в админке без блокировки заданий
→ встреча и пояснения участников
→ legitimate / monitor / penalty_recommended
→ при penalty_recommended: выбрать участника(ов) и сумму
→ атомарное подтверждение исхода и штрафа
```

Пока алерт открыт, новые взаимодействия обновляют тот же эпизод. Новый эпизод
возможен только после того, как число взаимодействий опустилось до актуального
порога и затем снова его пересекло. Приватные заметки встречи доступны только
активному администратору с правом `interaction_review` и не копируются в
уведомления или технические логи.
