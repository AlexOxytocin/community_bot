# Безопасность и приватность

## 1. Принципы

- Собирать только данные, необходимые для работы сообщества.
- Не считать Telegram username постоянным идентификатором; использовать Telegram user ID.
- Не показывать участникам скрытые административные данные.
- Не доверять данным callback и состоянию сообщения без повторной серверной проверки.
- Любые изменения экономики и ролей должны быть журналируемыми.

## 2. Секреты

- Токен Telegram-бота хранится только в переменных окружения или менеджере секретов.
- Токены, ключи и конфигурация production не коммитятся.
- Invite-коды хранятся в виде хеша.
- Логи не должны содержать токен бота, полные invite-коды и приватные комментарии кармы.

## 3. Авторизация

Каждый обработчик повторно проверяет:

- Telegram user ID;
- статус аккаунта;
- роль;
- разрешение уровня;
- принадлежность сущности участнику;
- допустимость перехода состояния.

Скрытая кнопка не считается защитой. Участник не должен получить административное действие через поддельный callback.

## 4. Карма

- Авторы оценок скрыты от обычных участников.
- Сырые комментарии доступны только автору оценки и администраторам.
- Экспорт доступных участнику профилей не содержит историю кармы.
- Администраторский просмотр оценок журналируется.
- История изменения оценок не удаляется обычными операциями.

## 5. Защита экономики

- Все начисления имеют уникальный ключ идемпотентности.
- Операции проводятся внутри транзакции базы данных.
- Повторный callback подтверждения не повторяет начисление.
- Нельзя принять собственное задание.
- Нельзя подтвердить одно выполнение дважды.
- Нельзя потратить зарезервированные кредиты второй раз.
- Периодическая сверка сравнивает кэш баланса и опыта с журналом.

## 6. Файлы и ссылки

- Ограничить размер и разрешённые типы файлов.
- Не исполнять загруженные файлы.
- Не загружать автоматически произвольные внешние URL на сервер.
- Проверять схему ссылок и запрещать исполняемые URI.
- Сохранять Telegram file ID, если постоянная локальная копия не требуется.

## 7. Приватность профиля

Если участнику разрешён просмотр конкретной карточки, в ней допустимы:

- отображаемое имя;
- город и часовой пояс по выбору;
- описание и цель;
- навыки и категории;
- опыт, уровень, карма, надёжность и агрегированная статистика.

Не публикуются:

- баланс кредитов другого человека;
- история операций;
- авторы и тексты кармы;
- страйки и внутренние комментарии;
- Telegram user ID;
- административный аудит.

Круг участников, которым доступна чужая карточка, остаётся открытым решением `Q-011`. Перечень допустимых полей не означает автоматическую публичность всех профилей внутри сообщества.

## 8. Удаление и выход

При выходе:

- профиль скрывается из активных списков;
- открытые задания закрываются или передаются на модерацию;
- история выполнений и экономических операций сохраняется для целостности;
- персональные необязательные поля могут быть очищены или псевдонимизированы;
- пользователь получает объяснение, какие данные сохраняются и почему.

## 9. Резервное копирование и восстановление

- Регулярное резервное копирование базы.
- Проверяемая процедура восстановления.
- Отдельное хранение production и тестовых данных.
- Запрет использовать реальные приватные комментарии в тестовых фикстурах.
