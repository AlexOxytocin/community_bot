# CB-35 - отчёт о реализации

## Результат

Создан единый plain-text presenter полной карточки задания. Предпросмотр,
каталог, подтверждение принятия и «Мои задания» теперь показывают автора,
описание шаблона, детали автора, инструкции исполнителю, критерий результата,
материалы, награду, срок и формат.

## Исправленная причина

Telegram-транспорт раньше выводил только `PublishedTask.description`, хотя
авторский контекст и ссылка сохранялись в `input_payload_json` и
`materials_json`. Предпросмотр имел отдельную сокращённую проекцию. Теперь все
точки используют один immutable task snapshot и один presenter.

## Гарантии

- поля авторского ввода берутся из сохранённой input-схемы без технических ключей;
- legacy-снапшоты сохраняют ранее валидированные произвольные поля;
- опасные URI отклоняются при создании и отбрасываются при показе старых данных;
- карточка укладывается в лимит Telegram и отправляется с `parse_mode=None`;
- весь task/assignment flow, включая community-task, доступен только в private chat;
- replay назначения не создаёт инверсию row-lock order;
- автор и исполнитель восстанавливают полный контекст через «Мои задания».
