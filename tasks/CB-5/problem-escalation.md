# CB-5 — эскалация планирования

## Причина

Два полных независимых plan review завершились `changes_requested`. Технические
расхождения собраны; до единственного финального исправления нужен один
продуктовый выбор владельца.

## Архив попыток

- `reviews/plan/attempt-01.md` — неканонический статус, несогласованный admin
  permission и неопределённая потеря eligibility.
- `reviews/plan/attempt-02.md` — неподтверждённая необратимость eligibility,
  лишнее право `restricted` и двусмысленность moderator raw read.

## Уже определённые исправления

Эти пункты не требуют нового решения владельца и войдут в финальный пакет:

1. `restricted` не получает безусловный self-read. Обычный профильный интерфейс
   показывает собственную карточку только при `active` и `paused`; конкретное
   разрешение `restricted` остаётся решением модератора вне CB-5.
2. Raw author/comment/history доступны только active administrator с
   `karma_review`, с обязательным audit. Moderator не получает raw data даже при
   поддельном permission token со стороны клиента.
3. D-005 и безусловные административные пункты PRD явно уточняются этой
   permission-gated границей.

## Единственный выбор владельца — жизненный цикл eligibility

### Вариант A — необратимый исторический факт (рекомендуется для MVP)

Первая валидная ненулевая full/partial выплата между парой навсегда фиксирует
факт взаимодействия. Refund, correction и reversal экономики его не удаляют.
Изменять оценку всё равно можно только когда оба участника `active`; suspension
или ban останавливают действие. Преимущество — простой воспроизводимый контракт
без новой сущности модераторского решения. Риск — после отмены мошеннической
выплаты факт взаимодействия остаётся, но нарушителя можно ограничить статусом.

### Вариант B — отзыв только отдельным решением о недействительном взаимодействии

Full/partial выплата создаёт eligibility, а отдельное журналируемое решение
модерации `interaction_invalidated` может отозвать конкретное основание. Право
остаётся, пока существует другое валидное основание между парой. Экономические
correction/reversal сами по себе eligibility не меняют. Преимущество — точная защита
от фиктивных взаимодействий; цена — новая сущность, права, аудит и реализация в
CB-13 до завершения CB-12.

## Финальный цикл после выбора

Одновременно исправить `needs-info.md`, `plan.md`, `test-plan.md` и при
необходимости `plan-source-context.md`, затем выполнить одну контрольную
эскалационную проверку полного пакета. Если она снова не одобрена, остановиться
для решения владельца.

## Решение владельца

Выбран вариант A: eligibility остаётся навсегда после первой валидной
оплаченной работы. Отдельное модераторское аннулирование взаимодействия в MVP не
вводится. После terminal payout не моделируются поздний dispute или refund;
последующие допустимые события ограничены экономическими correction/reversal и
не меняют eligibility.

После остановки контрольного ревью владелец отдельно разрешил исправить три
оставшихся текстовых противоречия без изменения поведения и возобновить
финальную проверку.
