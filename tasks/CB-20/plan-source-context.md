# CB-20 — контекст и источники плана

## Источник дефекта

- Jira CB-20: на чистой схеме невозможно штатно создать первого администратора.
- Дефект впервые найден в общей регрессии CB-16 и поэтому исправляется отдельной веткой.
- CB-20 блокирует завершение CB-16; полная регрессия будет повторена один раз после слияния
  всех регрессионных исправлений.

## Проверенные границы

- `members` хранит Telegram identity, роль, статус и административные разрешения.
- `audit_events` является append-only журналом и допускает системное событие без actor.
- `/invite_create` уже требует active administrator и работает через прикладной сервис регистрации.
- Runtime использует PostgreSQL 18 и асинхронный SQLAlchemy; новый внешний сервис не нужен.
- Durable provenance повторного bootstrap хранится существующим audit-событием, а не выводится из
  одной роли администратора.

## Ограничения

- Никакого ручного SQL в штатной инструкции.
- Никаких токенов, username или приватного Telegram payload в audit и логах.
- Команда предназначена только для первого запуска или чистого восстановления, а не для
  обычного управления ролями.
- Обычное восстановление backup с существующим active administrator не запускает bootstrap;
  conflict требует остановки и диагностики, а не ручного SQL.
- Структурное решение не меняется, поэтому новый ADR не требуется.
