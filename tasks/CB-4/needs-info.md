# CB-4 — решение владельца перед изменением продуктовых правил

## Почему требуется подтверждение

Восемь вопросов в канонической документации явно помечены как решения владельца. Они определяют экономику и пользовательские последствия, поэтому агент не может принять их молча.

## Рекомендуемый единый пакет

| Вопрос | Предложение |
|---|---|
| Q-002/Q-003 | Уровни: Первый шаг, Добрый импульс, Полезный вклад, Уверенный вклад, Весомый вклад, Сильный вклад, Значимый вклад, Большой вклад, Выдающийся вклад, Легенда; пороги 0/10/25/50/100/180/300/450/650/1000; все решения используют active-scale resolver, backfill кэша не меняет опыт |
| Q-004 | 5 стартовых кредитов один раз после одобрения, без опыта |
| Q-007 | Refund по каждому месту при отсутствии исполнителя или результата; своевременный result переходит в review; task агрегируется как expired/partially_completed/completed; `no_show` обратимо исключается при вине автора/системы |
| Q-008 | Review-окно `[submitted_at, submitted_at + 72 часа)`: ручное решение или спор допустимы только до точной границы, autoconfirm — на границе и позже; общий lock сериализует гонку, решение/спор подавляют напоминания 24/48 часов |
| Q-009 | 50% с округлением вверх из резерва одного assignment; partial только от 2 кредитов; выплаты 2→1, 3→2, 4→2 |
| Q-010 | Не более 2 assignments неупорядоченной пары по стабильному коду шаблона; якорь `accepted_at`, окно `(T-30 суток, T)`, active считается до завершения, политика версионируется без сброса истории |
| Q-012 | Отдельных общественных бонусов нет; вознаграждение только через фиксированный шаблон задания |

Полные формулировки, причины, исключения и миграционные последствия находятся в `plan.md`.

## Достаточный ответ

- `Подтверждаю пакет решений CB-4` — принять весь пакет;
- либо перечислить только изменения, например: `Q-008 — 48 часов вместо 72`.

До ответа задача остаётся в Jira в статусе `К выполнению`; продуктовые документы не изменяются.
