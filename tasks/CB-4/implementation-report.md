# CB-4 — отчёт о реализации

## Результат

Продуктовые решения владельца перенесены из одобренного плана в каноническую
документацию MVP. Область задачи сохранена: изменены только Markdown-документы;
Python-код, схема PostgreSQL и миграции не менялись. CB-4 в Jira находится в
статусе «В работе», ветка — `task/CB-4`.

Первый независимый final review получил `Status: changes_requested` и обнаружил
два остаточных противоречия. Общий алгоритм завершения и критерий этапа 4 теперь
явно разделены по `origin`, а устаревший handoff приведён к фактическому
состоянию проекта и активной конфигурации уровней.

Зафиксированы:

- версионируемая продуктовая конфигурация названий и порогов десяти уровней;
- однократный стартовый грант `5` кредитов без опыта;
- пер-слотовое истечение многоместных заданий и append-only коррекция `no_show`;
- проверка результата `72h`, напоминания `24/48`, отдельное окно спора после
  отклонения `24h` и замена независимого проверяющего;
- частичная выплата `ceil(50%)` с точными примерами и правилами резерва;
- отсутствие жёсткого лимита взаимодействий, алерт на четвёртом оплаченном
  взаимодействии пары за скользящие `7` суток и ручной исход после встречи;
- идемпотентный штраф только для `penalty_recommended`, без отрицательного
  баланса, резерва и изменения опыта;
- задания `origin=community` с автором «Сообщество», системной наградой,
  требованиями безопасности и независимой проверкой.

## Полная регрессия

Локальная среда приведена к CI-совместимой обработке LF через репозиторную
локальную настройку Git `core.autocrlf=input`; эта настройка не коммитится и не
меняет проектные файлы. PostgreSQL 18.4 работает в Docker Compose и имеет статус
healthy.

| Проверка | Результат |
|---|---|
| `uv sync --locked --all-groups` | успешно, Python среды проекта 3.13 |
| `uv run ruff format --check .` | все найденные Python-файлы соответствуют формату |
| `uv run ruff check .` | успешно |
| `uv run ty check src tests` | успешно |
| Alembic `upgrade → downgrade base → upgrade` | успешно на PostgreSQL 18.4 |
| `uv run pytest -ra` с Compose `DATABASE_URL` | `152 passed`, `0 skipped`, `0 deselected`, coverage `93.72%` |
| `uv build` | sdist и wheel собраны |
| `community-bot --check` | успешно, внешние действия не выполнялись |
| `community-worker --check` | успешно, внешние действия не выполнялись |

Первый локальный `ruff format --check` выявил только CRLF рабочего checkout при
глобальном Windows `core.autocrlf=true`. Репозиторная локальная настройка
`core.autocrlf=input` и механическая нормализация восстановили CI-эквивалентный
снимок; хэши Python-файлов совпали с `HEAD`, и ни один из них не входит в diff.

## Остаточные границы

- CB-4 не реализует описанные таблицы, миграции и обработчики: они переходят в
  зависимые Jira-задачи CB-7 и CB-9 после слияния решения.
- Открыты только независимые продуктовые вопросы `Q-001`, `Q-005`, `Q-006` и
  `Q-011`; они не были разрешены молча.
- До коммита и PR обязательны staged-проверки, независимый final review и CI.

## Отклонение от первоначального docs-impact

`docs/mvp/HANDOFF.md` и `tasks/CB-4/needs-info.md` не входили в первоначальный
перечень десяти канонических файлов. Они добавлены после сквозной проверки:
первый содержал противоположную инструкцию о названиях уровней и устаревшее
описание отсутствующего каркаса, второй продолжал показывать уже снятую фазовую
блокировку. Оба изменения документационные, прямо восстанавливают единый
источник истины и не расширяют runtime-область CB-4.
