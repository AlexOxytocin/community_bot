# CB-42 — контекст и источники плана

## Jira

- Задача: `CB-42` — «Свободное создание заданий с категориями, размером и наградой».
- Родительская задача или эпик: отсутствует.
- Комментарии: на момент планирования дополнительных комментариев нет.
- Связи и блокирующие зависимости: похожая открытая задача `CB-37` описывает компактные карточки и старую согласованную отмену, но не покрывает свободное создание задания и новую семантику завершения набора.
- Критерии приёмки:
  - создание задания не требует выбора пользовательского шаблона;
  - шаги мастера доступны через Telegram inline-меню или понятный текстовый ввод;
  - подсказки по типу, категории, размеру и текстовым полям показываются на текущем шаге;
  - категории берутся из конфигурации, `Развитие комьюнити` доступна только администраторам;
  - размер определяет допустимую награду;
  - итоговый резерв группового задания не превышает доступные кредиты автора;
  - лимиты текстов валидируются с понятной ошибкой;
  - предпросмотр позволяет изменить каждый пункт;
  - публикация идемпотентна;
  - старые опубликованные задания остаются читаемыми и исполнимыми;
  - завершение набора блокирует новые принятия, возвращает свободный резерв и сохраняет право уже принятых исполнителей сдать результат;
  - документация, доменные правила, интерфейс и тесты обновлены.

- Ветка задачи создана в отдельном worktree `C:\Users\User\community_bot_cb42` от актуального `origin/main`, чтобы не смешивать работу с незакоммиченными изменениями `CB-39` в основном каталоге.

  - шаги черновика: `input`, `deadline`, `format`, `materials`, `slots`, `preview`, `published`;

- `src/community_bot/transport/telegram/tasks.py`:

- `src/community_bot/transport/telegram/task_card.py`:
  - карточка умеет показывать снимок задания, но пока не показывает размер времени, категорию, число мест и полный резерв.

## Ограничения

- Нельзя удалять `task_templates`: старые задания и старые result schema должны остаться читаемыми.
- Новые пользовательские задания должны быть детерминированно валидированы кодом, без LLM.
- Кредиты резервируются одной транзакцией с публикацией и не резервируются повторно при replay.
- Telegram callback data должна укладываться в 64 bytes.
- Telegram Bot API не даёт live-счётчик символов во время набора обычного сообщения; MVP показывает лимит до ввода и результат валидации после отправки.
- Реальная Telegram-проверка рабочего экземпляра требует отдельного deploy после merge; локально можно закрыть PR-ready gate через output-driven fake Bot API и интеграционные тесты.

## Открытые вопросы

- Нет блокирующих вопросов. Принятые владельцем исключения: `XL` имеет любое целое число кредитов больше `10`; групповое задание принимает любое целое число исполнителей, ограниченное только доступными кредитами и технической целочисленной валидностью.
