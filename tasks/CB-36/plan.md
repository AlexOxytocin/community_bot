# CB-36 - план исправления

## Цель

Дать автору видимый и безопасный способ отменить своё опубликованное задание из
раздела «Мои задания» без ручного поиска UUID.

## Причина дефекта

Application service отмены и возврата резерва уже существует, но Telegram UI
доступен только через `/task_cancel <task-id>`. Карточка не показывает `task-id`
и не содержит соответствующего действия.

## Изменения

1. Добавить кнопку «Отменить» к собственной карточке со статусом `published`.
2. Первый callback использовать только для подтверждения без изменения данных.
3. Подтверждение направлять в существующий `TaskService.cancel`.
4. После успеха явно сообщать об отмене и возврате резерва.
5. Для задания с историей назначений показывать понятную причину отказа.
6. Не показывать кнопку у отменённых и терминальных заданий.
7. Сохранить private-only границу и лимит callback Telegram.

## Вне области

- отмена задания после появления исполнителя;
- изменение правил возврата резерва;
- удаление истории задания;
- изменение сценария отказа исполнителя от назначения.

## Риски

- случайный клик не должен сразу менять баланс;
- повторное подтверждение не должно возвращать резерв дважды;
- кнопка старого сообщения не должна обходить application authorization.

Риски закрываются двухшаговым callback, существующей транзакционной
идемпотентностью и проверкой владельца внутри application service.
