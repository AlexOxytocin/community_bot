# CB-36 - план проверки

## Автоматические проверки

1. «Мои задания» выдаёт карточку опубликованного задания с кнопкой «Отменить».
2. Первый callback показывает подтверждение и не меняет статус или баланс.
3. Подтверждение меняет статус на `cancelled` и возвращает резерв ровно один раз.
4. У отменённого и завершённого задания кнопка отсутствует.
5. При истории назначений callback даёт понятный отказ без изменения состояния.
6. Callback из группового чата отклоняется без вызова service.
7. Callback data не превышает 64 bytes и берётся из предыдущего ответа fake Bot API.

## Регрессия

- целевые transport и integration тесты;
- `ruff format --check`, `ruff check`, `ty check`, `git diff --check`;
- полный `pytest` перед merge.

## Production-проверка

После merge и deploy создать через живую Telegram-сессию одно временное задание,
открыть «Мои задания», нажать «Отменить», проверить экран подтверждения, подтвердить
отмену и убедиться в статусе `cancelled` и точном возврате резерва. После проверки
в production не должно остаться активного тестового задания.
