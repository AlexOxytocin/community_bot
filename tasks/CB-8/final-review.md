## Результат повторного ревью

### M-001 — закрыто

Реальный `/cancel` зарегистрирован в Telegram router и проходит через update/identity gates. Для регистрации он переводит persistent conversation в `registration_paused`, сохраняя шаг и payload; после этого ожидаемый ввод отсутствует, а запоздавший ответ не меняет профиль или черновик. Повтор той же команды возвращает сохранённый outcome. После `dispose/new Database` следующий `/start` возобновляет тот же member UUID, шаг и payload. Для редактирования профиля отменяется только диалог, подтверждённые поля профиля не меняются.

Поведение подтверждено кодом application/UoW/persistence/router, PostgreSQL integration-тестом и synthetic aiogram smoke: cancel → отсутствие ожидания → игнорирование запоздавшего ввода → restart/resume.

### M-002 — закрыто

В PostgreSQL integration-тестах появились и независимо прошли доказательства ранее отсутствовавших границ:

- expired invitation отклоняется;
- exact replay одного `/start` возвращает тот же результат и не создаёт второго участника;
- unauthorized moderation и fake target завершаются без grant/receipt и иных прикладных эффектов; путь ошибки находится до решения, аудита и применения гранта;
- approval retry после `dispose/new Database` остаётся идемпотентным и сохраняет ровно одну стартовую транзакцию;
- сохраняются и читаются все поля профиля: имя, город, часовой пояс, описание, цель, категории помощи, навыки и доступность;
- API редактирования не принимает чужой member ID и разрешает менять только профиль участника, найденного по Telegram identity; попытка другого участника не меняет целевой профиль;
- неактивному участнику редактирование запрещено без изменения профиля.

## Критерии Jira

Все семь критериев приёмки пройдены:

1. Действующее приглашение принимается в пределах лимита; revoked/expired отклоняются.
2. Повторный `/start` продолжает регистрацию и не создаёт второго участника.
3. Перезапуск сохраняет шаг и payload, включая pause/resume.
4. Pending-участник не получает active-права.
5. Активация атомарно создаёт ровно один `starting_grant` `+5/+0`; retry и конкурентные вызовы идемпотентны.
6. Смена Telegram username не создаёт новый аккаунт.
7. Приёмочный путь invitation → onboarding → moderation → profile проходит в targeted-контуре.
