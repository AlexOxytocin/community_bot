# CB-18 — план проверки

1. Обычная функциональная задача: готовый код → целевые/integration/smoke
   проверки → один final review → PR. Полная регрессия продукта не требуется.
2. Задача уровня 3 получает один plan review полного плана; промежуточные
   разделы отдельно не проверяются.
3. После первого непройденного ревью весь набор замечаний исправляется одним
   циклом. После второго создаётся `problem-escalation.md` и выполняется одно
   сводное исправление.
4. Общая регрессия начинается отдельной задачей после готовности всего MVP.
5. Баг общей регрессии получает отдельную Jira-задачу и ветку; дефект до неё
   остаётся в текущей задаче.
6. Один пользовательский результат со всеми слоями — одна задача. Две
   независимые ценности — две задачи под эпиком.
7. Старые формулировки о полной регрессии внутри каждой задачи отсутствуют в
   обновлённых процедурах.
8. `git diff --check`, YAML parse, Markdown links, язык и secret scan проходят.
