# CB-37 - эскалация после двух final review

## Причина

Две независимые финальные проверки завершились `changes_requested`. По
`docs/AGENT_WORKFLOW.md` дальнейшие точечные циклы запрещены: требуется один
консолидированный пакет исправлений и последняя независимая проверка.

## Консолидированный пакет

1. Применить deadline guard к обоим путям свободной отмены, включая фактический
   callback `task:cancel:do:*` и `/task_cancel`.
2. Добавить прямое чтение owned-card по `task_id` с полной проверкой владельца,
   без зависимости от страницы в 20 элементов.
3. Пронести `resolution_reason` через persistence, application outcome,
   идемпотентный receipt и Telegram-текст.
4. Добавить audit-событие немедленной отмены из negotiated-confirm race.
5. Зафиксировать каждый пункт отдельным regression oracle, повторить целевые
   проверки и полный локальный gate.

## Барьер

После этого пакета выполняется одна последняя независимая final-проверка. Если
она не вернёт `Status: approved`, PR, merge и production deploy останавливаются
до решения владельца.

## Результат последней проверки

Попытка 3 вернула `Status: changes_requested`. Четыре замечания попытки 2
закрыты, но один concurrency assertion остался на старом контракте, а заявленный
многоместный конкурентный oracle не реализован полностью. В соответствии с
барьером PR, merge и deploy остановлены до решения владельца.

Владелец явно разрешил продолжить после барьера. Разрешён один дополнительный
консолидированный пакет, полный локальный gate и независимая попытка 4.
