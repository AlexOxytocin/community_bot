# Роли агентов Community Bot

Роли описывают инженерный процесс Jira `CB`, а не будущие исполняемые роли самого Telegram-бота.

## Каталог

### `developer`

Основная роль по умолчанию. Ведёт Jira-задачу через приём, проверку готовности, планирование, ограниченную реализацию, тестирование, отчёт и передачу результата. Для малых воспроизводимых багфиксов уровня `1B` по ADR-0010 использует compact bugfix note вместо полного плана и отчёта. Прямое поручение на реализацию разрешает стандартную недеструктивную цепочку Jira → branch → PR → merge после обязательных checks → release → deploy; failed gate, конфликт, рост риска или разрушительное действие останавливают цепочку.

### `analyst-architect`

Опциональная роль. Активируется по прямому запросу для анализа требований, архитектурного решения, ADR или проверки консистентности. Не реализует код и не выполняет внешние изменения.

### `plan-reviewer`

Независимая роль только для чтения и смысловой проверки `plan.md` и `plan-source-context.md`. Обязательна для задач уровня 3, включая архитектурные, интеграционные, чувствительные к безопасности и насыщенные источниками; для малых задач запускается по необходимости.

### `final-review`

Обязательная независимая роль после `implementation-report.md` для уровней 2–3. Для уровня `1B` выполняет короткую diff-проверку compact bugfix note, фактической разницы, целевой проверки, секретов и признаков повышенного риска; локальный `final-review.md` создаётся только при явной необходимости. Не исправляет результат и не выполняет внешние изменения.

## Будущие исполняемые роли

Для будущего каталога рассматриваются общие архетипы:

- оркестрация;
- приём и нормализация;
- интерпретация и классификация;
- агрегация и сверка;
- предварительный просмотр и проверка человеком;
- детерминированное применение и завершение.

Фактический каталог исполняемых агентов Community Bot появится только после утверждения продуктовых сценариев.

## Общий контракт

Каждая роль содержит:

- стабильные идентификаторы правил;
- декларацию идемпотентности;
- закрытый список сценариев ошибок;
- версионированную схему результата;
- самопроверяемые критерии завершения.

Вердикты артефактов ревью всегда используют одно из точных значений:

```text
Status: approved
Status: changes_requested
Status: blocked
```

Все смысловые объяснения пишутся на русском. Технические идентификаторы сохраняются как есть.
